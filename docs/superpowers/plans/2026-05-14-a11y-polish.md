## Phase A — Reduced-motion respect (15 min)

**File:** `src/client/styles.css`

**Why second:** purely additive CSS. Wraps animations in `@media (prefers-reduced-motion: reduce)` block that neutralizes them. Existing motion stays for default users; vestibular-sensitive users get static UI.

**Approach:**
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

This is the canonical WCAG 2.3.3 pattern. Doesn't disable animations entirely (some frameworks break with `animation: none`) — collapses them to instant.

- [ ] **A.1** Append the @media block to `src/client/styles.css`.
- [ ] **A.2** npm gates + AI-tone scan + atomic commit.

## Phase B — ARIA live region on event stream (5 min)

**File:** `src/client/App.tsx`

**Why third:** screen readers announce new event arrivals as they're polled. WCAG 4.1.3 Status Messages.

**Approach:** add `aria-live="polite"` + `aria-atomic="false"` + `aria-relevant="additions"` to the event-stream container `<div>` (around line 133 — the `overflow-y-auto border-t border-line` div).

`aria-relevant="additions"` ensures the screen reader announces NEW rows only, not the entire list on every re-render.

- [ ] **B.1** Add 3 ARIA attributes to the event stream wrapper.
- [ ] **B.2** npm gates + AI-tone scan + atomic commit.

**Approach:** wrap the relative-time text in `<time datetime={new Date(refreshedAt).toISOString()}>`.
